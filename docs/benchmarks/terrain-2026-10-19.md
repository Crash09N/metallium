FPS cap. **AC power, 60 Hz display (E2211)**; the game window was mostly *unfocused* (the owner's desktop). Displayed fps

## Bench fix first

Every earlier bench run (all agents) rendered only the spawn area: Sodium `C: 92/2616` at "rd32". The bench set the
render-distance option without `Options.broadcastOptions()`, so the server kept sending chunks for the distance the client
joined with (5). Fixed in this branch; rd16 now loads 22 104 sections, rd32 83 064 sections (2 760 visible, 662 MiB
geometry shaders off / 1.24 GiB with Complementary). **Numbers recorded before this fix are not terrain numbers.**

## How Sodium submits terrain on Metal (verified in source and counters)

- Sodium picks `DrawBackend.OPENGL` for every non-Vulkan device. Per frame it calls
  `RenderPass.multiDrawIndexed(PointerBuffer offsets, IntBuffer counts, IntBuffer baseVertices, n)` once per
  (region, pass) with up to 1 793 sub-draws; batches are cached per region until its render list or the camera's
  relative section changes. No indirect draws, no GPU-side buffers for the draw lists.
- Metallium's backend encodes each sub-draw as one `drawIndexedPrimitives(…baseVertex…)` in the open render encoder.
  Terrain adds **no encoders**: render encoders per frame are 1–2 shaders off and ~27 with Complementary, unchanged
  when terrain is skipped.
- Cost of one sub-draw on the CPU: **~60 ns** (0.149 ms for 2 502 sub-draws).

## What this means for Phase 3

1. **Draw submission is not a bottleneck.** All of Sodium's terrain CPU work on the render thread is 0.07–0.29 ms per
   frame (rd16–rd32, shaders off/on); the Metal encode part is 0.06–0.22 ms. Turning those draws into Metal indirect
   draws would not reduce calls (Metal has no multi-draw); ICBs would, but Metal forbids encoder-bound textures in ICB
   pipelines (Sodium's terrain shader samples the atlas, lightmap and a texel buffer), so ICBs need an argument-buffer
   variant of the terrain/pack pipelines — a large change for at most ~0.2 ms CPU. **Not worth doing now.**
2. **Draw merging does not work**: only 3 of 2 502 sub-draws (rd32) continue the previous draw's vertex range in
   Sodium's arena, so adjacent-range merging cannot reduce calls. Implemented, measured, removed.
3. **GPU is where terrain costs with shaders**: Complementary rd32 spends ~1.0 ms GPU of 2.2 ms per frame on terrain,
   almost all of it in the main view (shadow terrain is small in this scene). Shaders off, terrain GPU is 0.3 ms (rd16)
   to ~1.8 ms (rd32). So GPU occlusion culling of the **main view** is the only Phase 3 lever with real headroom: its
   ceiling is the main-view terrain GPU time (~1 ms at Complementary rd32), its real gain is the occluded share of
   Sodium's already graph-culled sections (unknown; needs a prototype with a "culled sections" counter first).
4. The shadow pass must keep Iris's own culling (camera Hi-Z is wrong for the light's view) — and there is little to
   win there in this scene anyway.
